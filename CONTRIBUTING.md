# Contributing to Skill Evals

Thanks for your interest in contributing.

## How to contribute

### Reporting bugs

Open an issue. Include:
- What you expected to happen
- What actually happened
- Steps to reproduce
- Your Python version and OS

### Suggesting improvements

Open an issue first. Describe what you want to change and why. Wait for feedback before writing code.

### Submitting changes

1. Fork the repo
2. Create a branch from `main`
3. Make your changes
4. Run the notebook to make sure nothing broke
5. Open a pull request

### What makes a good PR

- One logical change per PR
- Clear description of what changed and why
- Tests pass (run the notebook)
- No unrelated formatting changes

## Code style

- Python: follow the existing style, run `ruff check` before committing
- Markdown: one sentence per line for easier diffs

## What we're looking for

- Bug fixes
- Documentation improvements
- New eval types (open an issue first to discuss)
- Improvements to existing evals
- Better error messages

## What we're not looking for

- Major architectural changes without discussion
- Dependencies on heavy ML frameworks
- Changes that break the notebook's stored outputs without re-running

## Questions?

Open an issue.
